# MineAI 发展方向

## 1. 产品定位

MineAI 的目标不是做通用桌面陪伴，而是做一个“能听懂中文、能解释自己、能在
Minecraft 世界里安全完成任务”的智能 NPC。

产品核心定义：

> 面向 Forge 1.20.1 的中文语音交互、任务执行和长期生存伙伴。

AIRI 的角色表现、会话体验和多模态交互可以作为参考，但 AIRI 不作为 MineAI
的运行时依赖。MineAI 的执行内核必须继续由 DeepSeek、豆包、Mineflayer、Forge
Bridge 和权限系统共同负责。

## 2. 总体架构方向

```text
玩家文字 / 豆包语音
        -> DeepSeek 中文认知层
        -> 任务规划与权限确认
        -> Mineflayer 状态机
        -> Mineflayer 技能 / Pathfinder / PVP / Tool
        -> Forge Bridge 与模组能力
        -> 环境反馈、后置验证、经验记录
        -> 中文聊天与豆包 TTS 回复
```

职责边界：

- DeepSeek 负责理解、解释和规划，不直接操作 Minecraft API。
- 状态机负责动作所有权、互斥、取消、恢复和验证。
- Mineflayer 负责原版世界交互。
- Forge Bridge 负责模组能力、客户端状态和严格停止确认。
- 豆包只负责语音输入和语音输出。
- 权限系统负责玩家身份、风险确认和拒绝策略。

## 3. 发展目标

### 目标 A：可靠执行型 NPC

优先把 MineAI 做成“少卡死、少重复、可停止、可恢复”的执行系统。

重点：

- 明确状态：待命、移动、跟随、采集、回避、恢复、验证、停止。
- 任意时刻只有一个动作拥有移动、库存或战斗写权限。
- 所有长动作必须支持取消和超时。
- Promise 完成不等于任务成功，必须验证世界状态。
- 停止、死亡、断线和新指令必须走统一中断路径。

验收标准：连续执行移动、跟随、采集、回避和停止任务时，不出现动作重叠，
迟到结果不能覆盖新任务。

### 目标 B：Voyager 式技能成长

不直接引入 Voyager，而是迁移它的四个方法：

1. 技能有明确的输入、前置条件、执行步骤、后置条件和失败原因。
2. 每次任务都收集环境快照和结构化结果。
3. 失败后由 DeepSeek 基于反馈重新规划，而不是盲目重复。
4. 成功任务沉淀为可复用技能经验。

建议新增技能经验结构：

```json
{
  "skill": "collectBlock",
  "context": "oak_log_nearby",
  "preconditions": ["has_pickaxe"],
  "postconditions": ["inventory.oak_log >= before + 1"],
  "result": "success",
  "failure_reason": null,
  "duration_ms": 4200
}
```

技能经验只影响规划建议，不能绕过权限、状态机或 Forge 安全边界。

### 目标 C：AIRI 式角色体验

借鉴 AIRI 的角色表现方向，但保持 Minecraft 场景优先：

- 中文人格稳定：称呼、语气、价值观和任务风格保持一致。
- 任务过程可解释：说明正在做什么、为什么失败、下一步是什么。
- 事件驱动表达：发现危险、完成采集、死亡恢复、回到玩家身边时主动反馈。
- 语音和文字内容一致，避免聊天回复和 TTS 回复分叉。
- 后续再建设角色档案、关系记忆、情绪标签和可选表达风格。

角色表现不能干扰任务执行，也不能用闲聊兜底替代 DeepSeek 的任务判断。

### 目标 D：Forge 模组智能化

Forge 是 MineAI 区别于普通 Mineflayer Bot 的核心竞争力。

优先建设：

- 模组能力发现和版本能力快照。
- Epic Fight、SlashBlade 等战斗能力的明确所有权。
- 女仆工作、农场、仓储和建造协作的结构化任务接口。
- Forge 状态过期、客户端断开、ACK 超时的失败闭环。
- Mineflayer 原版战斗只作为 Forge 不接管时的兜底。

## 4. 分阶段路线

### Phase 1：执行可靠性

状态：当前阶段。

- 完成状态机与 ActionManager 的统一接线。
- 保持默认关闭开关，完成真实世界烟雾测试后再启用。
- 固定 `mineflayer-tool`，验证工具选择和采集。
- 完成移动、跟随、采集、回避、停止、死亡恢复测试。
- 修复全量测试中与本次变更无关的 GPT 配置测试依赖问题。

### Phase 2：技能协议与环境反馈

当前进度：技能反馈协议、ActionManager 采集、有限重规划和中文 DeepSeek
反馈摘要注入已完成；长期技能经验沉淀待下一批实现。

- 为核心技能建立统一 Skill Contract。
- 记录前置快照、执行结果、后置快照和失败类型。
- 将失败目标、路径失败、库存不足和权限拒绝区分处理。
- DeepSeek 每轮最多选择一个可验证动作。
- 为 autonomy 增加基于反馈的有限重规划。

### Phase 3：长期任务与技能经验

当前进度：技能经验已实现有界持久化和启动加载，动作/失败/恢复/停止时延及
curriculum 阶段指标已接入；更丰富的成功经验抽象待后续实现。

- 将采集、工具制作、熔炉、铁器和生存循环组织为 curriculum。
- 保存成功技能的环境条件和适用范围。
- 对重复失败进行目标降级、换目标或暂停，而不是无限重试。
- 建立任务成功率、平均恢复次数和停止响应时间指标。

### Phase 4：角色和多模态体验

当前进度：已完成独立的有界 Agent Action Loop，并通过 feature flag 接入
SelfPrompter 的主动任务路径。该编排层每轮只允许一个经命令注册表和现有权限
策略校验的命令，支持取消、重复命令拒绝、权限/确认/库存失败停止重规划，并保留
结构化执行结果和技能反馈；AutonomyController 已通过独立 feature flag 接入，
并保留原有 curriculum、黑名单和有限重规划策略。

- 完成 bounded observe -> plan -> execute -> feedback 循环。
- DeepSeek planner 适配器只接收有界观察，不接触 bot、凭据或文件系统。
- AutonomyController 接入路径不新增模型调用，继续复用现有权限、状态机和紧急停止链。
- AutonomyController bounded Loop 已实现并默认关闭；专项 autonomy 测试覆盖上限、阶段目标和并发 guard。

- 增加角色档案和稳定人格配置。
- 增加任务进度、危险提醒、完成确认等事件表达。
- 优化豆包语音打断、回复时机和播放抑制。
- 设计可选的 Web 角色面板，但不让 UI 成为执行依赖。

### Phase 5：可扩展生态

当前进度：已完成第一版离线执行回放工具。回放使用真实命令注册表和 Loop 校验，
通过确定性 executor 验证成功、失败、取消、重复和非法命令，不连接 Minecraft、
Forge、模型或语音服务。

Skill Plugin 静态契约与显式注册表已实现；插件默认禁用，不自动扫描、加载或执行
第三方代码。

女仆式沉浸战斗第一阶段已实现纯逻辑 CombatController、威胁目标排序和战斗上下文
恢复测试；尚未接入 Mineflayer/Forge 执行器。

Phase 10-12 批次已完成安全边界实现：CombatArbiter 提供唯一 owner 和优先级抢占，
ForgeCombatAdapter 提供能力检查、结构化动作映射与 ACK 结果，语音路由支持保护、
攻击、撤退和停火四类高层战斗意图；Agent 已增加默认关闭的 Mineflayer fallback
接线。Forge adapter 仍需显式注入 Bridge 才能接管，不会自动伪造执行成功。

- 提供 `npm run replay -- <case.json>` 命令行入口。
- 回放报告包含停止原因、执行命令、结果和断言状态。

- 定义 MineAI Skill Plugin 接口。
- 允许新增原版技能、Forge 模组技能和只读观察工具。
- 每个插件必须声明权限、风险等级、输入约束、后置验证和停止行为。
- 提供离线回放测试，让技能在真实 Minecraft 连接前完成大部分验证。

## 5. 明确不做的事情

- 不直接嵌入 Voyager 的 Python/MineDojo/Fabric 运行时。
- 不直接嵌入 AIRI 的完整桌面 UI 或会话内核。
- 不让大模型直接执行任意 Mineflayer、Forge、Shell 或文件系统操作。
- 不同时启用 Mineflayer 和 Forge 两套战斗控制器。
- 不在没有兼容性矩阵的情况下升级 Mineflayer/Pathfinder。
- 不用角色闲聊掩盖任务失败或伪造执行成功。

## 6. 关键指标

| 指标 | 目标方向 |
| --- | --- |
| 动作重叠率 | 0 |
| 停止响应时间 | 本地动作快速停止，Forge 按 ACK/超时闭环 |
| 伪成功率 | 0 |
| 长任务成功率 | 随技能经验和反馈重规划逐阶段提升 |
| 重复失败次数 | 有界，达到上限后暂停并解释 |
| 中文意图误判率 | 持续通过语音/聊天回放下降 |
| 语音回复一致性 | 文字与 TTS 使用同一结构化回复 |
| Forge 能力误用率 | 0 |

## 7. 最终形态

MineAI 的最终形态应是：

- 交互上像 AIRI 一样自然、有连续人格和丰富反馈；
- 规划上吸收 Voyager 的技能积累和失败改进；
- 执行上依靠 Mineflayer 状态机、工具选择和后置验证；
- 能力上通过 Forge Bridge 深度理解 1.20.1 模组世界；
- 安全上所有高风险动作可确认、可停止、可审计、可恢复。

核心原则：先让 NPC 稳定完成任务，再让它变得更像一个角色；先保证事实反馈，
再增加自主性和表达性。
