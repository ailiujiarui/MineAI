# 输入管线:从有人跟她说话,到她的手按下去

一条线讲完她怎么接收输入、谁替她想、想完怎么落到身体上。合并了原来的 `mcp-server.md`(外接大脑)与 `companion-input.md`(身体的输入层)。
相关的另两份:收件箱的类型表与循环内核见 `agent-loop.md`,群聊的会话与记录见 `group-chat.md`。

## 一、全景

```
渠道(谁在跟她说话)        大脑(谁替她想)               身体(她做事)
游戏聊天 @她 ─┐                                          
面板、快捷对话 ┤                ┌─ 主人客户端代调模型 ─┐
/numen 命令 ──┼─► 收件箱 ──► 循环 ┤                      ├─► Lua 程序 ─► 任务 ─► 输入层(键盘、视角、鼠标、快捷栏)
QQ、Discord ──┤  (每只一个)      └─ 服务端直调模型 ────┘    (ServerPrograms)
弹幕、定时 ───┤        │                                          │
世界的事 ─────┘        └───────── 外接大脑(MCP)取件、发程序 ───────┘
```

三层两管:渠道把话送进收件箱;大脑从收件箱取件、交出 Lua 程序;身体在服务端跑程序,最后落到她的键盘和鼠标上。
加一个渠道不碰大脑,换一个大脑不碰渠道,谁驱动她都用同一副身体。

**现在与目标。** 10-05 "客户端想、服务端做"已经把 Lua 程序搬到服务端,身体那一段已经在服务端;收件箱、循环、她的记忆、外接大脑还在主人客户端,
所以主人一下线,她能把手上的活干完,但听不见、想不了。**目标(10-11 用户拍板):服务端必装,客户端可选,外接大脑放服务端。**
目标的部分 0.1.5 不做,0.1.5 主线是寻路;下文每节先写现状,再写目标。

## 二、渠道

| 渠道 | 现状 | 目标 | 她的回话送到哪 |
|---|---|---|---|
| 面板、快捷对话 | 客户端,`NumenGateway.emit` | 经网络包送进服务端收件箱 | 面板、打字机、语音 |
| 群聊(多人对她说话) | 已落地,见 `group-chat.md` | 不变 | 同上 |
| 插件桥接(弹幕、群消息) | 客户端,`NumenGateway.emit` | 走远程端点的渠道令牌(§五) | 原渠道 |
| 游戏聊天 @她 | 没有 | 服务端读聊天 | 聊天行、头顶气泡 |
| `/numen` 命令 | 只有管理类命令 | 加"对她说一句" | 命令回显 |
| 世界的事、定时 | 服务端 `NumenEvents.emit`,主人离线进出箱 | 直接进服务端收件箱 | 不需要回话 |

- 每条输入记着**从哪个渠道来、谁说的**。她说的话总在游戏里说出来(气泡、聊天行),另外送回问她的那个渠道:从 QQ 问的,QQ 上收到回答。
- **没装客户端也能用**:说话靠聊天 @她;征询卡变成一条带可点按钮的聊天消息(底层是现有的 `/numen consent`);她在干什么显示在动作栏或 Boss 栏;
  1.21.6 起可以用原版的服务端对话框做卡片。面板、语音、look 的渲染要客户端。

## 三、收件箱

现状:每只同伴一个,在主人客户端,入队即落盘、取走即清;投递方式(叫不叫醒她、随哪一次调模型交出去)写在类型表里,见 `agent-loop.md` §七。

目标:**搬到服务端,跟着她。** `EventQueue`、`EventTypes`、`JsonlJournal` 本来就在纯 Java 的 `agent` 模块里,原样搬。

- 入口合成服务端一个:`NumenEvents.emit` 与 `NumenGateway.emit` 并成一处,客户端的输入经网络包送进来。
- 出箱 `EventOutbox` 删掉:它存在是因为收件箱在客户端、主人离线时事件没处放;收件箱在服务端,离线只是"攒着"。

## 四、大脑

现状:循环内核 `AgentLoop`(纯 Java,`agent` 模块)跑在主人客户端,用主人的 key 调模型;外接大脑接管时循环停牌(`Hold.EXTERNAL`),
驾驶席只在 `McpMode.driving()` 一处判。

目标:**一份循环,放在服务端;"大脑在哪"只剩"模型由谁来调"。** 不是客户端、服务端各跑一份——那样换大脑时两份状态要对账,正是要避免的多源。

| 大脑 | 怎么跑 | key 在哪 | 什么时候用 |
|---|---|---|---|
| 主人客户端代调 | 服务端把一轮的请求发给主人客户端,客户端用主人的 key 调模型、流式回传 | 主人的电脑,永不上传 | 主人在线、装了客户端;现在的默认,只是循环换了位置 |
| 服务端直调 | 服务端自己调模型 | 服主的配置,按玩家配额 | 服主开了;主人下线后接班 |
| 外接大脑 | 循环停牌,远程 MCP 驾驶(§五) | 外接 agent 自己的 | 主人用自己的 Claude Code、Codex 一类 agent 指挥她 |

- 代调走 10-05 已有的"服务端反向请求客户端"(带超时、程序收尾撤销)。
- **代调只发增量,不每次发整份上下文。** 一轮上下文几万 token、一两百 KB,一次 run 里每调一次模型都要整份交给服务商;服务端到代调端这一跳不必跟着整份发。
  请求的结构本来就是"稳定前缀 + 只追加的历史 + 每次现算的小尾巴"(`architecture-mind-model.md` §三):系统提示与工具表按内容哈希,代调端没见过才发
  (同模块的哈希缓存一个做法);历史只发上次之后新追加的几条;运行期状态每次照发。代调端在内存里按会话拼回整份请求,只是缓存、不落盘、不是真源;
  哈希对不上(整理记忆换了摘要、断线重连)就整份重发一次。于是这一跳每次只有新的工具结果与主人的话,几 KB,和现在回执的量同级;
  MC 连接本身还有压缩。
- 打字机、语音、气泡、token 台账照旧订阅循环事件 `LoopEvent`,事件经网络包推给在线的主人客户端。
- 主人下线后怎么接班,主人给每只同伴选一项:停下待命(默认)、外接大脑接班、服务端大脑接班(服主允许时);主人上线交还他选的大脑。
  模型请求本身是无状态的,状态都在服务端的循环里,所以区别只在"用谁的 key、用谁的脑子":外接大脑是主人自己的 agent 用自己的 key 借她的身体;
  服务端大脑是她自己的循环用服主的 key。"她自己的循环 + 主人自己的 key + 主人不在线"这一格(主人机器上常驻一个代调程序)现在不做,有人真要再加。
  身体本来就不随主人下线休眠(`CompanionChunkLoader` 在她周围保持 3×3 区块),所以接上一个能想的大脑就是全天候。
- 主人不在时要问的事:征询发到主人接得到的渠道(QQ、Discord……,渠道令牌认的是主人本人);哪里都找不到他,到时按拒绝,她只做本来就放行的事。
- 单人游戏是同一进程里的内置服务端,路径一样,不多一跳网络。

## 五、外接大脑

### 现状:主人本机起一个 MCP 服务器

外部 AI 客户端(Claude Desktop、Claude Code、Cursor 或任何支持 MCP 的东西)直接驱动她。驱动期间内置大脑停手——同一具身体同一时刻只有一个脑;
主人在游戏里照常和她说话,话进同一条事件线,由外接大脑接走并回话。

**一条线:事件出、说话回。**

- `get_events(companion, wait_seconds)`:长轮询取件。主人的话(`<query>`)、世界里的事都从这一个口出去;急件一到整批返回;取走即消费,两次调用之间不丢。
  默认等 2 秒(停靠期间外接大脑做不了别的事,两秒一取才能既听得见主人、又腾得出手主动行动),最大 50 秒。外接大脑自己的程序等着收尾的长活,收工写进程序回执,不在这里;
  程序被打断时还在跑的活,收工才是这里的一条 `task_finished`。
- `say(companion, text)`:她开口——头顶气泡、聊天栏、绑定声线的语音;连续的 say 排队连播。
- 其余工具与内置大脑相同:`lua`、`skill`、`todo`、`memory`。
- **对话历史外接大脑自己记**,游戏侧无状态;面板画的是现场(最近的话与动作行,纯内存,关游戏即弃)。目标里改为同时记进她在服务端的那本日志(§六)。
- **失联**:安静超过约两分钟聊天栏提示;开了"失联后内置大脑接管"则内脑临时接手,外脑回来即交还。

**怎么开。** `G` → 设置 → 外接大脑,右上角开关。概览页:端点、令牌(只显示前几位,可复制、可重新生成——旧令牌立刻作废)、连接状态、
失联接管开关、**复制接入提示词**(一段话粘给你的 AI,它自己配好连接;**含完整令牌**,只发给信任的 AI)。设置页:

| 项 | 默认 | 说明 |
|---|---|---|
| 允许局域网连接 | 关 | 关 = 只有本机连得上 |
| 端口 | `8765` | 被占就换 |
| 调用超时(秒) | `300` | 长活受理即回;短的同步动作做完才回;要问主人的等到答复 |
| 不暴露给外部的工具 | 空 | 逗号分隔 |

界面上改的落在 `config/numen/mcp_server.json`(`enabled`、`host`、`port`、`token`、`call_timeout_seconds`、`hidden_tools`、`quiet_fallback`),
界面没给的值(如绑某张网卡)直接改文件,重进世界生效。

**安全。** 默认只绑回环 `127.0.0.1`,外面够不着。放开监听地址后,同一网络里任何设备连上就能操控她:开了局域网而令牌为空时保存会被拦;
令牌首次启动由 `SecureRandom` 生成,别换成好记的短串;觉得泄露就重新生成。Numen 不替你做防火墙。

**出问题时。** 开关拨不动多半是端口被占,换端口重存(原因标在端口输入框上);外部客户端连不上,确认开关开着、地址与令牌是复制的、
不在本机时开了局域网;她不理聊天框,看外接大脑有没有在 `get_events`。日志搜 `[numen-mcp]`。

### 目标:服务端一个远程端点,所有人共用

外接大脑挂在客户端,主人一下线就没人能操控她。搬到服务端,一个服务器一个端点:

- **按令牌认人。** 主人用 `/numen token` 发令牌,随时作废;存档只存哈希;照 MCP 的授权规范做。
- **令牌带作用域**:能指挥自己名下的哪几只;角色是**大脑**(取件、发程序、说话,等于驾驶)或**渠道**(只能把话送进收件箱、收她的回话)。
  Claude Code 拿大脑令牌,QQ 机器人拿渠道令牌——插件桥接从此也走这里,不再挂在客户端上。
- **权限不会因令牌变大**:外接大脑的程序同样过权限层,主体是那只同伴。
- **限流**:每个令牌限并发与频率,服主可配总量。
- **协议**:Streamable HTTP,多会话;`get_events`、`say` 等工具不变。
- **端口**:先做"服主自己开端口,建议套反向代理加 HTTPS";再调研"和 MC 共用一个端口,按开头几个字节分流";中继服务等用的人多了再说。

## 六、她的记忆存在哪

现状:对话、札记、待办、长期目标、人设、技能、模块真源都在主人客户端 `config/numen/`;服务端只按哈希在内存里缓存她的模块。

目标:大脑可以换,换了以后她还得记得自己干过什么——夜里服务端大脑做了什么,早上主人上线她要知道。所以:

| 数据 | 存哪 | 理由 |
|---|---|---|
| 收件箱、对话历史、札记、待办、长期目标、人设 | 服务端,跟着这只同伴 | 她在这个世界里的经历,换哪个大脑都读同一份 |
| 模块与技能(她的手艺) | 主人客户端是个人库;服务端落一份副本 | 手艺要能带去别的世界;主人在线时照现在的哈希缓存同步,副本落盘,主人不在时离线大脑用副本 |
| 模型服务商与 key | 哪个大脑调模型就在哪一边 | key 不跟着数据走 |

- **落在世界存档里**:`<存档>/numen/companions/<她的 uuid>/`。备份世界就连她一起备份,删世界她也跟着走;每个世界的她各有各的经历。
  旧的客户端记录(`config/numen/conversations/<uuid>.jsonl` 等)按她的 uuid 在主人首次上线时迁上去。
- **客户端不留副本**:面板打开时向服务端分页取,之后跟着实时事件长;只在内存里。
- **群聊照旧"存储按人、视图按会话"**(`group-chat.md` §七),只是那本日志换到服务端。
- **外接大脑驾驶的那段也记进同一本**:进来的话与事件、她 `say` 出口的话、程序与回执。外接 agent 自己的思考留在它那边。
  这样换回内置大脑时,她知道刚才发生了什么。
- 变长靠现有的整理(摘要替换更早的历史),规则不变。

代价照实说:服主看得到她的对话与札记。她的身体本来就在服主的机器上;单机没有这个问题。面板上可一键导出、清空她的记忆。
10-11 用户定:只存服务端,不做"只放主人电脑"的选项,也不做下线交接。

**显示照旧只给主人。** 存在哪与谁看得见是两回事:头顶气泡、聊天栏里她的话、语音现在只在主人客户端上(`SpeechBubbles`:她的思考与发言是主人的私事),
这一点不变。没装客户端时,她的回话用只发给主人的系统消息,不进公共聊天。

## 七、身体的输入层(已落地)

她是没有客户端的服务端玩家。真人手里的键盘、视角、鼠标、快捷栏,她都有,而且**只此一份、谁驱动她都用同一份**——寻路、Numen 的工具、
第三方插件、外接大脑的程序,最后都按这几样让她动。参照:Mineflayer 本体的 `setControlState`/`lookAt`/`dig`/`activateItem`、Carpet 的
`EntityPlayerActionPack`、Baritone 的 `InputOverrideHandler`——都是一层统一的"玩家输入",粒度就是真人能按的东西,寻路建在它上面。

全在 Numen API 的公开包 `com.dwinovo.numen.api.entity`,进瘦 jar:

```java
NumenPlayer her;
her.controls()  // 键盘:前后左右、跳、潜行、疾跑
her.look()      // 视角:at(点)、turn(朝向)、faceToward(x, z);看向一格方块上她看得见的那一点或那一面
her.mouse()     // 鼠标:pick/on/itemRay 准星;dig/attack/release 左键;use/useItem/stopUse 右键;intents() 此刻要问许可的意图
her.hotbar()    // 快捷栏:hold(格)、grip(东西),每次换了都交回 BodyAction
```

- **粒度就是真人的输入。** "挖掉那一格""放一块到那里"这类组合不进这一层,是使用者用这四件拼出来的。四件都是"一具服务端玩家 + 状态"的小类,
  普通假玩家也能 `new` 来用(寻路的 `TestBody`)。
- **鼠标只对准星起作用。** 先 `look()` 转过去再按;`mouse()` 自己做准星拾取,"手点到了哪一格"只有一个出处。要的是某一格时先问 `on(pos)`。
- **每一下如实交回结果。** 左键交回 `Strike`(还在挖 / 挖掉了什么 / 被拒及理由 / 准星没落在方块上);右键交回 `Use`(缓手没按 / 按了:落着什么、
  世界变了哪几格、打开了什么界面 / 被拒)。点格子、点空气、点实体是同一个右键、同一种结果,`numen.use.*` 都从它写回执。右键按住(拉弓、吃喝、举盾)
  与左键按住挖一样归鼠标管,两次按下的间隔是鼠标的事。
- **权限长在鼠标上。** 左键换到新的一格时问能不能拆;右键会往世界里放东西时问能不能放,否则问能不能用。要问主人时鼠标停下、交回 `Refusal.Asks`,
  由驱动者决定怎么问(寻路是走到那一格停下问);不许是 `Refusal.Denied`;服务端把挖掘退回来是 `Refusal.Server`(身体汇报,不是裁决)。
  判据只认身体是谁:是同伴就过权限层,普通假玩家照原版;别人自己 `new` 一个同伴的鼠标也绕不过去。
- **原版公式只有一个出处。** `DigTime`(挖掘进度与冷却,从 `DigTime.Mining` 算,不碰真身体也能算)、`Reach`、`Sight`、`Faces`、`Replaceable`
  身体与寻路规划共用;挑工具归 `ToolChoice.take`。纯规划的几何(`Footing`、`Stepping`、`Clearance`)与规划用的身体快照留在 pathing。
- **换驱动者时统一松手。** `CompanionBrain` 每刻只选一个驱动者(反射 > 同步 > 当前任务 > 空闲姿态),换人那一刻调完旧驱动者的 `stop` 就把键全松、
  挖掘进度清零、右键松开,新驱动者从干净的身体开始;任务与反射不各自松键。
- **寻路怎么接。** 身体端口 `Body` 留在 pathing,交出那具玩家与这四件,寻路直接用;`Ports` 里只剩寻路自己的策略。

## 八、安全:第三方服务器上谁防谁

服务端必装以后,她多半活在别人的服务器上。三方各有要防的,分开说:

**1. 玩家防服务器。** 服务器上的一切(背包、房子、公共聊天)本来就在服主手里,她的记忆跟着身体住在那里,这一层只能靠信任,做到的是说清楚、可撤回:

- **按服务器授权,像浏览器按网站给权限。** 第一次带她进一个多人服时,客户端弹一张卡说清这个服务器要什么:存她的记忆(服主看得到)、
  借你的 key 代调模型(上限多少)。你可以只答应一部分;不借 key 时,她在这个服只能用服务端大脑(服主出钱)或待命。单机不弹。
- **不变量:主人的 key 不出主人的机器。** 没有任何一条代码路径把它发给服务端;要用到它就走代调,服务端只拿到模型的回复。
  任何调模型的进程都必须读得到明文,加密存放挡不住那台机器的主人,所以唯一可靠的是 key 不去第三方服务器。
  主人自己开的服例外:服主就是他,可以把 key 填进服务端配置。
- **额度上限防"不偷 key、借你的 key 花钱"。** 恶意服务端可以伪造代调请求跑它自己的东西,也可以刷急件反复叫醒她;客户端分不出真假,
  所以按服务器设上限(每天花多少、每小时最多叫醒几次),到了就停并提醒;第一次进服默认给一个小额度;token 台账按服务器分开记。
  最坏就是花完你给这个服的额度。
- **服务商那边再兜一道。** 界面与文档提醒:给 Numen 单独建一个 key,在服务商后台设花费上限(OpenRouter 的单 key 额度、Anthropic 工作区与 OpenAI 项目的预算)。
- **key 碰不到的地方。** 不进日志、不进模型上下文(提示注入问不出来);Lua 沙箱没有文件与系统访问,服务端大脑的 key 玩家的程序也读不到。
- **AI 特色服、要把 key 交给服务器的玩法**,只能明确提醒:交出去的 key 服主拿得到,只交设了花费上限的那一个。
- **客户端函数只读。** 反向请求能让你的客户端做的事只有只读的查询与渲染,没有副作用(10-05 定的 SDK 约定),服务端借不到你电脑上的别的东西。
- **看得见、删得掉。** 面板上写明"她的记忆存在这个服务器上",一键导出、一键清空。

**2. 服务器防玩家。** 玩家提交的 Lua 在服务端跑,没装客户端的玩家也能提交:

- 沙箱上限(指令数、字符串、时长)、每个主人同时几段、主线程每刻预算,都由服主可配(10-05 已有,改成可配)。
- 服务端大脑按玩家配额;远程端点按令牌限并发与频率,服主可配总量。
- 远程端点默认关;令牌高强度随机、只存哈希、可设过期、随时作废、带作用域;开了明文 HTTP 时界面与日志警告,建议反向代理加 HTTPS;每次接入与调用记审计日志。
- 服主的总开关:能不能用 Numen、能不能用服务端大脑、能不能开远程端点、能不能夺舍,各自一个。

**3. 玩家防玩家。** 不让她成为搞破坏的工具:

- 权限层的硬规则:别人的东西拆不得、拿不得、打不得,主人点"允许"也解不开(`permission-layer.md` §六)。
- **专用服务器上"说不清是谁的"按别人的算**(硬拒),服主可改;单机与局域网照旧问主人。否则别人装模组前盖的房子,
  一个想搞破坏的主人点一下"允许"就拆了。
- 提示注入:只有主人与群聊成员的话算命令,别人在聊天里 @她、QQ 与弹幕渠道进来的话都标着来源;模型就算被说动,
  动手也过权限层,越不过主人本身的权限,更越不过硬规则。

## 九、以后:夺舍

主人下线时,用和主人同一个身份的假玩家顶替主人的身体干活(像 Carpet 的 `/player shadow`)。在这条管线里只是"换一个身体来源",渠道、收件箱、大脑都不变。
要单独定:上线时的交接(防复制物品)、主人明确授权与范围、死亡与危险保护、服主开关、回来时完整交代做了什么。不在本方案里做。

## 十、分步落地(0.1.5 之后)

每一步单人游戏行为不变,日常 GameTest 两个加载器全过。

1. **收件箱搬服务端**:入口合一、出箱删掉、条目带渠道与说话人;客户端面板经同步包读。
2. **循环搬服务端**:`ModelPort` 的"主人客户端代调"走反向请求;呈现订阅经网络包;驾驶席三选一。
3. **记忆搬服务端**:对话、札记、待办、目标、人设落在同伴存档;模块与技能副本落盘;面板导出与清空;旧的客户端数据首次上线时迁上去。
4. **远程端点**:`McpServer` 搬服务端;令牌、作用域、限流、多会话;插件桥接改用渠道令牌。
5. **无客户端交互**:聊天 @她、可点的征询消息、动作栏状态、1.21.6+ 对话框。
   安全(§八)不单独成一步:每一步把它涉及的那几条一起做——第 2 步带按服务器授权与额度上限,第 4 步带令牌与审计,第 6 步带配额与服主开关。
6. **服务端大脑与全天候**:服主配置服务商与 key、按玩家配额;征询发到渠道;主人下线后的接班选项。
