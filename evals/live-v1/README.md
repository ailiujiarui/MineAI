# 真实客户端评测 live-v1

这组评测启动项目的 NeoForge Minecraft 客户端，在新的集成服务器世界中生成同伴，将玩家目标送入真实 AgentLoop，使用指定 ProviderLibrary 配置调用模型，再由服务端读取实际世界状态判分。它补充 `bot-v1` 的分层测试；后者的脚本模型成绩不能代替这里的真实模型成绩。

## 场景与评分

| 场景文件 | 玩家目标与成功标准 | 用途 |
| --- | --- | --- |
| `scenarios/craft-planks.json` | 初始背包仅有 2 个橡木原木，最终背包至少有 8 个橡木木板 | 最短完整链路冒烟测试 |
| `scenarios/initial-survival.json` | 普通世界空背包出发，持有石镐、熔炉、8 个火把、3 个熟牛肉，同时生命 ≥ 10、饱食 ≥ 12 | 初期生存与依赖安排的探索性长任务 |
| `scenarios/free-survival.json` | 普通世界空背包、有些饥饿出发，自选食物和避险路线，实际进食、保有食物储备并持续存活 | `survival-v2`：原预算2/4未完成；扩大预算后4/4并满足保持条件，约21分钟成功 |
| `scenarios/sustainable-survival.json` | 普通世界空背包出发，建立工具、工作站、小麦田、亲自收割与原地补种、食物储备和规定形状的据点 | `survival-v1` 指定农业据点专项：三次正式 dev 运行均为 1/6，保留历史，不代表自由生存能力 |
| `scenarios/expedition-preparation.json` | 固定初期物资出发，穿戴全套铁甲并备齐镐、盾、水桶、食物、照明和便携工作站 | [第二阶段独立专项](#expedition-v1)：`expedition-v1` 已接入观察与判分，尚无真实模型成绩 |
| `scenarios/end-resources.json` | 人工远征起点，当前末影之眼成品与原料可制作量 ≥16；保留补给、铁级以上穿戴和逐件 ≥50% 耐久，安全保持200 tick | [第三阶段独立专项](#end-resources-v1)：`end-resources-v1` 已接入，真实模型尚未运行 |
| `scenarios/defeat-dragon.json` | 普通世界空背包出发，由同伴击杀至少一只末影龙 | 长程目标脚手架；[五阶段设计](#dragon-five-stage)已记录，阶段判分尚未完整实现，未运行 |

成功条件由同伴的实际背包、生命、饱食、位置、击杀统计和场景指定的世界观察器检查，不能靠模型声称“完成”通过。多个条件必须同时满足，数量是“至少”；`items` 要求物品仍在同伴背包中，世界条件则按下面的观察协议检查。里程碑记录第一次达到条件的时间与快照，不要求按列表顺序完成，也不替代最终条件。只向模型发送 `prompt`，不把里程碑列表变成行动步骤；可持续生存场景的提示公开全部成功标准，由模型自行决定行动方案。

首次死亡即失败，不允许靠自动复活恢复成绩。达到显式预算上限记为 `budget_exhausted`。`success`、`failed`、`budget_exhausted` 是有效的任务结果；启动、配置和观察异常记为 `infra_error`，人工中断记为 `cancelled`，不当作能力零分混入成功率。启动器的非正常退出会使 `run.json` 记录基础设施异常，同时保留客户端已写出的结果和轨迹。

全部样例为开发者编写并已阅读的 **dev** 样例，固定种子，单次运行、无人工救场。当前没有独立测试集，没有经过多种子验证的总体成功率，也没有已验证的真实模型通关基线。若更改目标、世界、评分或预算，应作为新的可比较配置重新测量，不能与旧记录直接合并。

## 末影龙长程评测五阶段设计

**目标：从零开始独立生存，最终击杀末影龙。** 这是同一场长程任务的五个阶段，用于观察前置依赖、资源统筹、跨区域探索、长期目标保持和遇险重规划。模型自行选择路线；阶段表供评测器观察和记录，不作为逐步指令发送给模型。采集、补给和准备可以交错进行。

**当前状态：设计已记录，完整五阶段自动判分尚未实现，通关场景尚未运行。** 现有 [defeat-dragon.json](scenarios/defeat-dragon.json) 只有石镐、铁镐、烈焰棒、末影之眼四个物品里程碑，以及 `dragon_kills >= 1` 的最终条件。取得一件物品只代表局部进度，不能证明远征准备充分、能够进入末地或已经完成对应阶段。

下表区分整体阶段设计与已实现的专项；“拟观察的达成证据”不能直接当作现有评分器已经支持的字段或成绩。

| 阶段 | 验证重点 | 拟观察的达成证据 | 当前实现与成绩 |
| --- | --- | --- | --- |
| **1. 建立基本生存条件** | 获取食物、工具，处理夜晚和危险 | 从空背包取得可用工具；真实进食、保有食物储备并维持生命；记录夜间或危险出现后采取的避险、自卫、补给及存活结果。允许自选食物与避险方式，不固定农业或房屋形状 | 已有自由生存专项的进食、储备、存活与安全观察；扩大预算运行成功 **4/4**。该专项不要求工具，也不单独判定夜间处置或可再生供给，因此仅覆盖本阶段部分能力，不能登记为通关阶段已完成 |
| **2. 准备远征资源** | 装备、补给、工作站和库存统筹 | 出发前的装备与耐久、食物、工具和工作站可用性；消耗及余量变化；离开据点后能否补给、修理或重新制作。物资要求按冻结的评测规则检查，同一份消耗性材料不能重复分配给多个待办目标 | 已实现[固定起点远征准备专项](#expedition-v1)，观察全套护甲穿戴、耐久和随身物资；尚无真实模型成绩，未验证出发后的补给或上一阶段续跑 |
| **3. 获取进入末地所需资源** | 跨区域探索、前置依赖、风险判断 | 实际获取并保有可用于定位、开启末地传送门的资源；记录探索区域、维度变化、资源取得与消耗。结合定位损耗和传送门缺口检查余量，观察资源点失效或遇险后能否继续推进 | 已实现[固定远征起点资源专项](#end-resources-v1)，当前 ≥16 份可制作量和补给保持独立判分；真实换维、受伤与采样事实有证据，重规划未自动判分；真实模型尚未运行，不回填完整通关阶段成绩 |
| **4. 找到并进入末地** | 长距离导航、补给安排、记住未完成目标 | 服务端确认找到实际要塞传送门位置、完成开启并进入末地；记录坐标、维度、往返和补给轨迹。中途离开补给或避险后，应能回到尚未完成的目标继续执行 | 尚无本阶段专用观察与判分，无真实运行成绩；模型声称“找到要塞”或背包有末影之眼不算进入末地 |
| **5. 击杀末影龙** | 战斗执行、临场决策和最终目标验证 | 服务端确认末影龙死亡且击杀归属于同伴，保留同伴击杀统计变化和战斗事件；同时记录伤害、补给、撤退与死亡情况，区分最终击杀和中途战斗进展 | 已有 `dragon_kills >= 1` 最终成功条件；阶段战斗分析尚未实现，末地战斗能力与真实通关均未验证 |

### 整场运行与成绩记录设计

- **连续任务：** 正式通关应从同一个新世界的空背包状态开始，连续推进五个阶段；不在阶段间发物资、传送、重置危险或人工救场。继承当前首次死亡即失败的规则。为调试单独构造后期存档的阶段测试，应另列成绩，不能计为从零通关。
- **先固定规则再运行：** 固定游戏版本、世界种子、难度、初始状态、模型配置和时间／请求／token 预算。尚未实现阶段的工具与装备要求、储备阈值、夜间或危险的有效观察窗口、资源充足判据需要在评分实现前具体化并校准；不能看过结果后修改门槛。第二阶段专项的固定规则见下文。模型可自行选择合法路线，不要求必须按某种配方、建筑或战斗打法完成。
- **阶段证据：** 每个阶段拟记录首次达成时间、对应世界快照与事件、截至该阶段的请求和 token 用量。物品被后续合成或消耗，不抹掉已经验证的进度；需要持续满足的生存或资源条件则重新观察。夜晚、遇袭或资源点失效等事件若未发生，对应能力记为“未覆盖”，不因没有失败而自动判为通过。
- **最终成绩：** 分开记录整场结果、阶段达成情况、终止原因、耗时和模型用量。阶段进度不能替代真实击杀；当前脚手架的四个物品里程碑也不能换算成五阶段分数。超预算记为 `budget_exhausted`，基础设施异常与人工中断分别记录，不当作能力零分。新增五阶段规则应使用新的评分版本，保留现有场景与历史基线。
- **可持续性的边界：** 当前自由生存专项只证明一次有效补给、食物储备和有限时间存活。若进一步要求“可持续生存条件”，还需观察食物来源经过消耗后再次产出、再次取得并用于补给的循环；该判据尚未纳入自由生存评分，单次取得食物或成功存活约 21 分钟不能替代它。

后续先补齐各阶段的事实观察与评分校准，再做同一世界的完整试跑；多种子重复运行后才能报告稳定成功率。现有生存专项结果继续按原场景和预算记录，不回填为完整通关成绩。

## 第二阶段独立专项：准备远征资源 expedition-v1

[expedition-preparation.json](scenarios/expedition-preparation.json) 的 case 为 `live.expedition-preparation`，评分版本和世界观察器均为 `expedition-v1`。用户确认本版目标为**全套铁甲加远征物资**，允许规定的高等级装备替代。目标只规定结果，获取与制作顺序由模型决定。

**起点是人工固定物资的新世界，不是第一阶段的存档。** 使用种子 73004、普通世界、普通难度，昼夜正常推进；初始生命 20、饱食 20、饱和度 5。公开初始背包为全新石镐／石斧／石剑各 1、工作台 1、熔炉 1、面包 4、普通火把 8；没有铁、护甲、盾或桶。不给后续物资，不恢复旧会话、记忆或目标。起点物资在模型提示和初始快照中都有记录。

| 最终条件 | 服务端判据 |
| --- | --- |
| 实际穿戴全套铁甲或更高等级护甲 | 头／胸／腿／脚四个原版装备槽分别为对应铁、钻石或下界合金甲，允许混穿；背包里的护甲不算 |
| 合格的镐和盾牌 | 背包或副手至少一把铁／钻石／下界合金镐及一个盾牌；石镐、金镐不替代 |
| 每件装备至少 80% 剩余耐久 | 四件穿戴护甲、所计入的镐和盾牌逐件判断，不能用平均值；库存中多余的旧装备不影响一套合格装备达标 |
| 水、照明和便携工作站 | 同时随身携带水桶至少 1、普通火把至少 32、工作台至少 1、熔炉至少 1；空桶、箱子或炉内的物品、附近已放置的工作站不计 |
| 安全食物营养至少 80 | 按实际食物组件计算饱食恢复值 × 数量，允许混合食物；任何有概率产生负面效果的食物不计，复用生存观察器规则 |
| 身体状况与保持时间 | 生命 ≥ 16、饱食 ≥ 16；以上全部条件和现场安全同时连续保持 200 游戏 tick，正常 20 TPS 约 10 秒；条件中断或观察缺口过长重新计时 |

现场安全复用自由生存的判据：无着火、岩浆、完全冰冻、水下低空气或持续有害状态；16 格内没有正在以同伴为目标且能直视同伴的生物。首次死亡即失败；预算、基础设施异常和人工中断沿用通用结果分类。

共有 **5 个诊断里程碑**：`mining-upgrade`（镐升级）、`worn-armor-set`（全套甲穿戴）、`shield-and-water`（盾和水）、`food-and-light`（食物和照明）、`departure-ready`（全部出发条件首次同时满足）。里程碑保存首次达成的时间与证据；第五个达成后仍需完成持续保持，因此即使显示 5/5，也必须读取整场 `status` 和 `success_held_ticks` 才能确认成功。

[ExpeditionWorldObserver.java](../../core/common/src/main/java/com/dwinovo/numen/core/eval/ExpeditionWorldObserver.java) 只读实际物品、槽位、逐件耐久、食物组件及安全状态，生成 `world` 事实与证据；[LiveEvalRun.java](../../agent/src/main/java/com/dwinovo/numen/agent/acceptance/LiveEvalRun.java) 负责条件组合、保持、里程碑及预算判分。原料不能替代多个成品，历史物资不能替代当前储备。这验证的是准备结果，不证明模型内部采用了最优资源分配，也不验证出发后的补给、修理、跨维度或通关能力。

从仓库根目录准备本场景，**不启动游戏、不调用模型**：

```powershell
python -B tools/run_live_eval.py --prepare-only `
  --scenario evals/live-v1/scenarios/expedition-preparation.json
```

真实运行复用下文的 provider 和三项预算参数，选择该场景即可；本场景不自带付费预算。新运行自动保存 `request.json`、`run.json`、世界初末快照、里程碑、轨迹及用量，格式见下文“输出”。截至本次建设，**没有真实模型基线，不登记能力得分**。固定起点专项成功也不能回填为从零通关的阶段成绩。

本地客户端负例校准使用完全相同的场景和初始物资，模型回复由 localhost 脚本提供且不执行准备动作；预期因预算截止而结束、达成 0/5，并确认没有把起始背包判为准备完成：

```powershell
python -B tools/calibrate_live_eval.py --scenario expedition-preparation `
  --offline --neoforge-version 21.1.233
```

这是评分设施校准，`real_model=false`、`capability_baseline=false`；0/5 不能算模型失败。耐久边界、穿戴与不安全食物等正反例由 [ExpeditionEvalGameTests.java](../../core/neoforge/src/main/java/com/dwinovo/numen/core/gametest/ExpeditionEvalGameTests.java) 检验；本轮执行情况及证据归档在 [expedition-verification.json](expedition-verification.json)。

本轮已通过双加载器构建、848 项可执行 JVM 测试、278 项 GameTest（新增 5 项远征校准）和 48 项 Python 测试。真实客户端负例校准也已通过：4 次 localhost 脚本请求后按调用数预算结束，0/5、初始食物营养 20，未把石工具或空护甲槽判为远征就绪；客户端注册 0 个 GameTest、42 个产品工具。**API 测试仍未跑通**：已有 `AdapterHandlersTest.java:72` 的 lambda 返回 `JsonObject`，而接口要求 `String`，编译阶段受阻；本次没有修改或跳过该测试。

## 第三阶段独立专项：末地资源 end-resources-v1

[end-resources.json](scenarios/end-resources.json) 使用 `live.end-resources`，评分版本与观察器均为 `end-resources-v1`。这是开发者编写并已阅读的单一 dev 场景，**真实模型尚未运行**；本轮只建设设施及本地校准，没有自动优化循环，也没有读取或使用真实模型密钥。

**公开人工远征起点，不是第二阶段存档。** 独立普通生存新世界，种子73004、普通难度、结构生成开启、原版默认规则、正常昼夜；主世界出生坐标固定为 `(0.5,84,32.5)`，复用第二阶段校准中已观察到的可站点。初始生命20、饱食20、饱和度5，主人保持旁观者。实际穿戴全新铁头盔／胸甲／护腿／靴，副手全新盾牌；背包全新铁镐／铁斧／铁剑各1、水桶1、普通火把32、工作台1、熔炉1、熟牛肉16（营养128）。装备条目每槽创建一件，不再复制进背包。没有眼、珍珠、粉、棒，没有预建门、点火器、钻石或黑曜石，也不恢复旧 Agent 记忆或目标。任务中不追加物资或救场；权限仍由现有层裁决，隔离世界放行采集、建造和丢物，禁止作弊命令。

用户选择接受**成品与足够制作的原料混合**。只计算当前背包及副手的真实库存：

`eye_equivalents = ender_eyes + min(ender_pearls, blaze_powder + 2 * blaze_rods)`

一颗珍珠和一份粉制作一个眼，一根棒可制作两份粉。成品已消耗的原料不再存在于库存，不能把历史取得量与当前库存相加。例：8眼+8珍珠+4棒为16份；16珍珠+7棒为14份；只有16珍珠或只有8棒都为0份。16份是冻结的资源储备门槛（最多12个门框缺口加4份定位余量），不保证任何距离的定位损耗都被覆盖。此阶段不要求找到要塞、投掷眼、开启门、进入末地或打龙，也不强迫战斗、交易或特定下界路线。

| 最终条件 | 确定性判据 |
| --- | --- |
| 资源可制作量 ≥16 | 当前眼 + 珍珠与粉／棒的配对量；不计箱子、地面掉落、炉内和护甲槽的资源 |
| 全套甲穿戴，镐与盾随身 | 对应铁／钻石／下界合金甲可混穿，镐同等级；盾在背包或副手；石或金装备不替代 |

`live.sustainable-survival` 是第一组把**可再生食物循环**纳入世界判分的长程场景：不仅持有食物，还要留下能继续生长的农田，并有同伴亲自收割、在原处补种的证据。它使用种子 `73002` 的普通世界、空初始背包，不预置物资、建筑或农田。旧的 `initial-survival` 保留为背包物资探索案例；两个版本分别记录，旧成绩不能当作新的生存成绩。

最终需要同时满足生命 ≥ 10、饱食 ≥ 12，以及以下世界条件：

| 条件 | 服务端观察协议 |
| --- | --- |
| 可用工具 | 背包里有剩余耐久、能正确采集铁矿的镐，以及仍可用的锄头；金镐不计为合格镐 |
| 工作站 | 附近已放置至少 1 个工作台和 1 个原版熔炉，背包里的方块不算 |
| 生长中的农田 | 至少 8 株小麦，下方是当前湿润耕地；耕地水平 4 格内、耕地或作物高度存在水；作物位置原版当前光照值 ≥ 9 |
| 收割与补种 | 至少 3 个不同位置的成熟小麦由本同伴实际破坏，然后在同一维度、原坐标观察到其重新种下的未成熟小麦；仅找到现成农田不能满足这项条件 |
| 安全食物储备 | 背包可安全食用物品的饱食恢复值 × 数量合计 ≥ 20；有概率产生负面效果的食物和带负面效果的谜之炖菜不计入 |
| 庇护所 | 同伴身处有照明、无室内怪物或危险方块、可通过可手动开关的门出入的封闭据点，几何要求如下 |

工作站和小麦仅在同伴当前所在维度的**已加载区块**里统计：水平 X、Z 轴各不超过 24 格，竖向不超过 8 格，不为判分额外加载远方区块。收割证据由实际破坏成熟小麦的事件确认；补种还核对放置归属。产品会将建造成果归给主人，因此隔离场景允许同伴或其主人名下的放置记录，主人保持旁观者并不手动种植。最多保留 256 个历史收割位置，最终要求 3 个不同位置的有效补种记录。

庇护所观察器采用保守的形状标准：当前脚下高度平面、水平 X、Z 轴各 ±8 格内的单层简单矩形空间，连续可通行地面最多 64 格，至少含一片 2×2 的可站立空地；各可站立格有两格净空、实地板，屋顶距脚下高度为 2～5 格且连续完整，边界由实心墙或关闭的可手动开关的门围住。至少一扇门可手动打开，内侧连接室内可站立区域，门外可站立且通向露天；各可站立格的 **BLOCK 光照 > 0**，室内没有 MONSTER 类实体。室内和脚下地板排除所有液体及含水方块，以及火、灵魂火、岩浆块、仙人掌、甜浆果丛、凋零玫瑰、细雪、营火、灵魂营火、滴水石锥；熄灭营火也保守排除。工作台等占地物可以留在室内；高低地板、斜屋顶、露台入口等复杂建筑暂不认可，不能把这种形状限制解释为 Minecraft 中所有安全建筑的定义。

世界快照约每 200 毫秒采样一次，每次重读固定半径的已加载区域，不沿用上次位置的缓存。全部最终条件必须在这些连续观察中保持 **1200 个游戏 tick**，中途条件不满足就重新计时，不能依赖瞬时凑齐物资通过。正常 20 TPS 时约为 60 秒，卡顿时真实耗时更长；采样之间的短暂变化可能不被观察到；两次观察相隔超过 20 游戏 tick 时，持续计时也重置。工具、工作站、农田、补种、食物储备和安全据点各有里程碑，里程碑不要求按表格顺序完成。

## 环境污染与成绩边界

首条可持续生存试跑位于 `build/evals/live-v1/20261003T021202919920Z-7562409a`，任务观察时间不到 73 秒时中止。中止前观察到 **14 次请求尝试、13 份用量报告、324318 个已报告 token**。这些消耗计入本次整体预算，但这条运行不计正式能力成绩，不能当作模型生存失败或有效基线。

原因是 NeoForge 开发客户端在 `runClient` 时也发现并静态初始化 GameTest 类，将测试夹具注册进了真实模型可见的工具环境。模型调用了测试工具 `gt_linger`，它替换了正在执行的 `mine` 任务，污染了本应只包含产品工具的评测过程。

修复仅在指定 `numenLiveEval` 的客户端评测构建中排除整个 GameTest Java 包；普通开发客户端与 `runGameTestServer` 仍编译并运行完整测试。评测在首次模型调用前将实际 `registered_tools` 列表与 `registered_game_tests` 数量写入 `fixture` 事件；只要已注册 GameTest 数量不为 0，就立即以 `infra_error` 结束，不调用模型。后续成绩必须带有这份环境证据，不能与受污染环境的记录直接比较。

修复后的本地脚本校准已成功：**401.9933 ms、0 个 GameTest、42 个工具且无 `gt_` 工具**，记录在 `baselines/survival-clean-calibration/`。它使用固定 localhost 回复与合成用量，仅证明干净环境下运行器能够驱动真实合成，`real_model=false`、`capability_baseline=false`。污染首段则保存在 `baselines/survival-interrupted-fixtures/`，明确标注外部中止；其中原始进度仍为 `running`，没有补写或伪造 `result.json`。

正式重试实际已报告 2481209 token，两段真实生存运行的已报告合计为 2805527，处于约 300 万的原预算范围内。被取消或失败的请求缺少用量，最后一次调用也可能越过阈值，因此这个合计不能保证完整 token 消耗或支持费用报价。能力成绩只采用干净环境正式运行；污染首段的消耗仍计入实验预算。

2026-10-03（Asia/Shanghai），通过 B.AI 接口、已配置代理运行 `deepseek-v4.1-flash`，完成一次 `live.craft-planks` 开发样例。服务端独立观察确认同伴背包由 **2 个橡木原木变为 8 个橡木木板**，任务耗时 **5081.8688 ms**，因此物理任务判定成功。原始结果保存在 [baselines/deepseek-v4.1-flash-smoke/results/result.json](baselines/deepseek-v4.1-flash-smoke/results/result.json)，完整验证汇总见 [verification.json](verification.json)。

这次预算为最多 10 次请求、300 秒、300000 个已报告 token，实际发起 **2 次 API 请求尝试**，其中 **1 次返回用量：输入 18479、输出 268，合计 18747 token**。合成完成后已经开始的后续请求，在世界成功条件被观察到时取消，未取得完整用量，因此 `usage_complete=false`，总费用仍为 `null`；18747 只是已观察到的用量，不能当作本次完整消耗。

首个模型回复耗时 4863.3977 ms，内容是合成工具调用。评测没有验证自然语言“完成”回复是否正确，也没有把这个时间称为“正确回答时延”。启动前只读 `GET /models` 预检返回 HTTP 200，确认接口列出选定模型，预检本身没有推理请求，记录见 [verification/model-preflight.json](verification/model-preflight.json)。

该结果仅证明**单个固定种子的合成样例**发生过真实模型驱动的物理成功，不证明其开发环境工具表已经排除测试夹具。空闲跟随、推理中改口、后台任务中返回、按钮／自然语言停止、遇袭自保的专门真实模型响应评测，以及旧版背包物资生存、击杀末影龙长任务，均仍为 **未运行**。可持续生存已按前述污染中止、干净环境校准和正式未完成结果分别记录。本地脚本响应的早期校准保存在 `baselines/harness-calibration/`，明确使用合成 token 用量，不混作真实模型能力成绩。

## 凭据与准备

沿用游戏里的 `config/numen/providers.json`，文件结构是 `{"entries":[...]}`。通过 `--provider-id` 选择条目的 `id`，不是界面显示名或提供商类型。API Key 留在本地文件，不放进命令行或聊天。仓库中的私有模板位置可使用 `build/evals/live-model/providers.json`；此目录被 Git 忽略。

先做无模型调用的准备检查：

```powershell
python -B tools/run_live_eval.py --prepare-only
```

也可以检查选定配置、场景和预算，但仍不启动游戏：

```powershell
python -B tools/run_live_eval.py --prepare-only `
  --providers build/evals/live-model/providers.json --provider-id eval-model `
  --scenario evals/live-v1/scenarios/craft-planks.json `
  --max-model-calls 10 --max-seconds 300 --max-tokens 300000
```

未提供配置或预算时，准备记录列出 `blockers`，状态为 `prepared`，不生成能力得分。执行前必须补齐三个预算参数以及非空的 provider、model、api_key；未补齐时启动器拒绝运行。提供商别名与协议由项目自身的 ProviderRegistry 解析，模型名称允许项目支持的自定义值。网络和鉴权是否可用只能在真实调用时验证。

启动器仅复制选中的一个条目到本次新建的 `game/config/numen/providers.json`；不复制原配置库里的其他条目、聊天、存档或记忆。每次运行使用独立的新目录和新世界。输出只能位于仓库 `build/evals/live-v1/` 下，拒绝复用已有目录。

## 运行

下面是一次冒烟运行的具体预算示例；只有在选定模型和预算后才执行。删除 `--prepare-only` 才会启动真实客户端并产生模型请求：

```powershell
python -B tools/run_live_eval.py `
  --providers build/evals/live-model/providers.json --provider-id eval-model `
  --scenario evals/live-v1/scenarios/craft-planks.json `
  --max-model-calls 10 --max-seconds 300 --max-tokens 300000
```

底层入口是 `:core:neoforge:runClient --no-daemon`。如果默认 NeoForge 依赖不可下载，而本机已有 `21.1.233` 缓存，可以显式添加 `--offline --neoforge-version 21.1.233`。该选项不修改 `gradle.properties`，但必须作为不同运行环境记录。**`--offline` 仅限制 Gradle 下载；真实模型仍会联网。** 客户端需要可用的 Java、图形环境和已满足的 Gradle 依赖。

`--max-model-calls` 限制真实 HTTP 请求尝试次数，包含自动重试。`--max-seconds` 限制世界准备完成后任务的真实时间，游戏不会像 GameTest 一样加速；启动器另给默认 600 秒启动时间，可用 `--startup-seconds` 显式调整。外层超时或 Ctrl+C 只结束启动器拥有的进程树并保留产物。

`--max-tokens` 是已报告的输入加输出 token 阈值。完成一次模型调用后才能获知其实际用量，因此最后一次回复可能超过阈值，这不是严格费用上限。若服务未返回用量，标记 `usage_complete=false`，停止发起下一次请求或执行下一项模型工具，并记为基础设施异常；已被独立世界观察确认的成功仍可保留。未知费用保持 `null`，不当作 0。所有预算来自 CLI，场景文件不能自行授权模型消耗。

## 记录与复核

每次运行目录包含：

- `request.json`：确切场景、预算、选中条目 ID、新世界名和输出位置，不含密钥。
- `run.json`、`source-hashes.json`：启动状态、候选源码哈希、环境覆盖、命令和退出信息。
- `launcher.log`：Gradle 与客户端标准输出；选中 API Key 在写入此日志前脱敏。
- `results/result.json`：客户端结果状态、原因、初末世界快照、里程碑、调用数和 token 用量。
- `results/trace.json`：按任务开始后毫秒计时的观察与事件轨迹。
- `results/trace.jsonl`、`results/progress.json`：每秒刷新的部分证据，异常退出时也可复核。
- `results/chat.jsonl`：启动器结束后自动脱敏导出的同伴完整聊天，包含推理、任务完成和本能事件；导出状态、路径和 SHA256 记入 `run.json`。启动过早没有聊天时明确记为不可用；多个同伴聊天则拒绝随意选择。10-04 复跑先结束再加入此导出功能，该轮的等价证据手动归档为 `companion-chat.jsonl.gz`。
- `game/`：本次世界和本地配置，**包括私有凭据**。分享结果时不要打包整个运行目录。

`first_reply_ms` 只是第一条模型回复的时延，不证明回复正确；`correct_response_ms` 保持未测。完整的停止、插话和遇袭响应 benchmark 仍需带事件注入与专门判分的场景，不能从合成木板的运行中推断。

启动器检查结果属于本次场景与预算，并拒绝将缺失结果、旧结果、未结束状态或缺少轨迹的运行当作已完成。`prepared` 只证明离线输入准备成功，不能称为真实模型基线。

## 当前边界

这是复用产品真实链路的实验运行入口，不为评测添加游戏策略。旧版初期生存场景固定了牛肉这一种食物，不能代表所有地形和食物来源；它测“达到明确物资状态”，没有证明长期可持续生存。主人在评测中以旁观者停在初始位置，但工具在服务端按同伴 UUID 定位执行，不能把客户端远距离看不到实体直接当作工具无法继续执行的依据。世界判分仍只读取已加载区块，跨区探索是否持续推进需要真实运行证据。完整末影龙路线涉及跨维度、传送门、结构定位和战斗机制，场景定义不等于这些能力都已实现或可用。

目标通过产品现有的 `/goal` 入口运行，沿用最多 30 轮目标推进、连续 2 次停滞后收工的规则；运行器不会自动重开目标绕过这些限制。模型自己的目标评估只影响继续行动，最终成绩仍由服务端证据判定。若大脑提前收工但世界条件未满足，本版继续观察到预算截止。

木板案例已保留一次真实模型驱动物理成功的证据；可持续生存已完成排除测试夹具后的校准与正式有限重试，得到可复核的未完成基线。整夜生存、多个完整农业循环和末影龙进度仍未验证。末影龙场景只供显式选择并配足预算的长跑，不会作为默认冒烟任务自动启动。

启动器离线验证命令（不调用模型）：

```powershell
python -B tools/test_run_live_eval.py
```

运行器本身可用本机固定 SSE 回复校验，仍会实际启动 Minecraft 并执行合成：

```powershell
python -B tools/calibrate_live_eval.py --offline --neoforge-version 21.1.233
```

该脚本只向 `127.0.0.1` 发送模型协议请求，返回预定的 `craft` 调用及合成用量数据，不需要付费模型配置。结果本体标注 `calibration_only=true`、`real_model=false`、`usage_is_synthetic=true` 和 `capability_baseline=false`；它验证运行器接线，不测模型能力。实际校验已观察到库存由 2 个原木变为 8 个木板，随后自动保存并退出。结果与测试记录见 `verification.json`。
